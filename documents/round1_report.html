Executive Summary
What BrandSentry AI is and why it matters
The Core Problem

Enterprise marketing and sales teams produce thousands of content assets every quarter. Each piece must comply with evolving brand guidelines, legal disclaimers, and regulatory standards. Today this review is manual — slow, inconsistent, expensive, and fundamentally unable to scale.

The BrandSentry AI Solution

BrandSentry AI is an AI-powered compliance engine that ingests brand guidelines as a structured knowledge base and reviews content via a three-layer pipeline: deterministic pre-filter, adaptive multi-strategy RAG retrieval, and policy-aware prompt chaining. The system outputs per-sentence, per-clause verdicts with calibrated cascaded confidence scores, cited evidence, and actionable rewrites. A dedicated semantic drift detection engine using presupposition mining catches implied violations that no keyword tool or generic LLM can detect.

Problem Statement & Market Context
Why brand compliance review is fundamentally broken today

🔴 Pain Point 1: Manual Review Cannot Scale

A single brand manager reviews 50–200 assets per week. The pipeline becomes a bottleneck as companies grow, with 3–5 day turnaround times slowing go-to-market velocity significantly.

🔴 Pain Point 2: Inconsistent Enforcement

Different reviewers apply guidelines differently. The same claim may pass one reviewer and fail another. No auditable, reproducible decision trail exists to reference or dispute verdicts.

🔴 Pain Point 3: Implied Violations Go Undetected

Keyword tools catch exact phrase matches but miss implied claims — content that avoids banned phrases yet still violates the spirit of a guideline. These semantic loopholes are the most dangerous compliance gaps.

🔴 Pain Point 4: Policy Changes Create Blind Spots

Brand guidelines update regularly. Content approved under an old policy may violate the new version. Without version tracking, entire content libraries become compliance liabilities overnight.

⚠
Real-World ConsequenceRegulatory fines for non-compliant marketing content in pharmaceutical, financial, and consumer goods sectors routinely exceed $1M per incident. Brand violations also damage customer trust and require costly public corrections.

⚡ Layer 1 — Deterministic Pre-Filter

  • Regex pattern matching for banned phrases, formatting rules, required disclaimers

🔗 Layer 3 — Policy-Aware Prompt Chain

  • Step 2 — Policy Mapper: assigns most relevant policy clause to each claim
  • Step 3 — Verdict Generator: reasons per-claim against its mapped policy context
  • Result: per-sentence, per-clause verdicts with full traceability

📋 Output — Structured Review Report

  • Sentence-level diff view highlighting each flagged claim
  • Cited policy clause + version for every flag (no hallucinated citations)
  • Cascaded confidence score with full intermediate trace

Technical Differentiators
Five capabilities that make BrandSentry AI uniquely defensible

🎯 Differentiator 1 — Semantic Drift Detection via Presupposition Mining

Most tools check if content contains banned phrases. BrandSentry runs a two-phase implied-claim extraction pipeline borrowed from computational linguistics:

1
Explicit Claim Extraction
LLM lists every factual assertion as atomic claims: "Company is #1", "No competitor equals it"
2
Presupposition Mining ⭐
LLM extracts what must be true: "Market share data exists", "Claim is independently verified"
3
Per-Claim Policy Validation
Each atomic claim and presupposition independently validated against policy embeddings

🔗 Differentiator 2 — Policy-Aware Prompt Chaining (Per-Sentence Granularity)

A 3-step chain: Claim Decomposer → Policy Mapper → Verdict Generator. Each atomic claim is evaluated against its specifically mapped policy clause, producing per-sentence, per-clause verdicts — dramatically more granular than any existing tool that returns paragraph-level judgments.

⚡ Differentiator 3 — Adaptive Multi-Strategy Retrieval

A claim-type classifier selects the optimal retrieval strategy per claim: dense vector for factual, BM25 hybrid for regulatory, graph traversal for comparative. No other RAG compliance tool adapts retrieval method to claim semantics.

📈 Differentiator 4 — Cascaded Uncertainty Propagation

Confidence is a Bayesian product across three pipeline stages. If any stage falls below 0.50, the final verdict is forced to INSUFFICIENT EVIDENCE regardless of LLM output — eliminating overconfident hallucinated verdicts.

📊 Differentiator 5 — Claim Fingerprinting + Policy Version Awareness

Semantically equivalent claims hashed and cached in Redis — repeat submissions get instant verdicts (<100ms, ~40–60% cost reduction). Every review stamped with policy version; when guidelines update, previously approved content is automatically flagged for re-review.

Three-Way Verdict System & Cascaded Confidence Scoring
Why "Not Found" does not equal "False" — and why cascaded uncertainty beats a single score
✅
SUPPORTED
Claim explicitly backed by retrieved policy content. Policy citation provided.
🔴
CONTRADICTED
Claim directly or implicitly violates a retrieved policy clause. Action required.
⚠
INSUFFICIENT EVIDENCE
No relevant policy found. Human review recommended — not auto-approved.
⚠
Critical Design Decision: "Not Found" does not mean "Approved"A naive RAG system treats absence of a policy match as implicit permission. BrandSentry AI treats it as uncertainty and routes to a human review queue — the correct behavior in compliance-critical systems where false negatives carry regulatory risk.

Security, Validation & Privacy
Enterprise-grade trust from the ground up

🔒 Prompt Injection Defence

All user-submitted content is treated as data, never as instructions. The system prompt forbids the LLM from following any directives found inside the content field. Input is sanitized and wrapped in structural delimiters before concatenation.

🏢 Workspace Tenant Isolation

Each brand client operates in a fully isolated namespace. Policy embeddings, review history, and API keys are scoped to the tenant. Cross-tenant data leakage is architecturally impossible — no shared vector indices or database tables.

🔗 Citation ID Validation

The LLM is only permitted to reference policy chunks using pre-assigned chunk IDs passed in the system context. Server-side validation rejects any citation ID not in the current retrieval set, making fabricated citations structurally impossible.

🔑 Auth & Secrets

  • JWT-based auth for all API endpoints
  • Workspace-scoped API keys with configurable expiry
  • No secrets in source code; all via environment variables
  • Rate limiting per workspace to prevent abuse

🎯 LLM-as-Judge Adversarial Benchmark
🔨 Attacker LLM Generates Evasions
A separate "attacker" LLM generates 50 content variants designed to evade detection: near-miss violations, paraphrased banned claims, and implied violations buried inside long sentences. Dynamically generated to probe the system's weakest points.
📊 Defender Score = Evasion Catch Rate
BrandSentry AI is scored on adversarial variants it correctly flags. Target: "defender score" >80% on the attacker set. This adversarial benchmark is far more rigorous than a static precision/recall test set and signals genuine engineering confidence.
